# Учись, вспоминая

**Планировщик самообучения вокруг одного принципа: знание остаётся не когда читаешь, а когда вспоминаешь.**

Single-file HTML-дашборд: открывается в браузере, работает офлайн, без сервера и аккаунтов. Внутри - метод, недельный план и редактор, который подстраивает день под живой ритм.

[▶ Демо](https://aysvoch.github.io/uchis-vspominaya/) · [Формат кода переноса](docs/generate-transfer-code.md)

## Проблема

Самообучение выглядит продуктивным, но легко превращается в имитацию: много чтения, мало воспроизведения. Без системы не ответить на базовые вопросы:

- **Сколько реально усвоено?** Прогресс привыкли мерить часами за столом - но часы не говорят, сколько осталось в голове.
- **Сколько часов из дня эффективны?** После 4-6 часов глубокого фокуса идёт не учёба, а её видимость.

Готовые трекеры и курсы навязывают чужой ритм и не заточены под обучение через вспоминание. Нужен лёгкий инструмент под сам метод, а не под чужой формат.

## Решение

Метод и инструмент под него. Метод - это три правила и одна метрика:

```
Принцип: вспоминаешь > читаешь
      |
      v
3 правила:  потолок 4-6ч глубокой работы  ·  блоки 50/10  ·  ежедневное вспоминание
      |
      v
День = 3 блока на одну тему
   ├─ Теория   впитываешь новое
   ├─ Проект   делаешь руками
   └─ Кейсы    тренируешь мышление
      |
      v
Метрика: доля вспомненного без подсказки  (не часы)
```

Инструмент - один HTML-файл: логика, стили и шрифты внутри, данные в localStorage браузера. Ни бэкенда, ни сборки, ни зависимостей - положил файл на любой статический хостинг (здесь GitHub Pages) или открыл локально.

## Ключевые механики

**Редактируемое расписание.** Жёсткий день не держится: снаружи тренировки, дела, срывы. Поэтому блоки - леса, а не рельсы. Правка времени блока, сдвиг всего дня, перестановка блоков с пересчётом времени встык, «идеальный день» от времени подъёма, свои блоки и описания с откатом к шаблону.

**Программа как код.** Состояние недели упаковывается в один текстовый код (JSON или ссылка). Вставил его в «Загрузить из кода» - расписание, блоки и источники прописались сами. Отсюда сценарий: просишь ИИ собрать код недели под свою тему по готовой схеме и получаешь заполненный план без ручной возни. [Формат и промпт](docs/generate-transfer-code.md).

**Источники в каждом блоке.** У блока есть поле «Где искать»: не просто «изучи retention», а «изучи retention - вот где брать». Тема без источника - это ещё не план.

## Почему доля вспомненного, а не часы

Часы за столом - удобная, но лживая метрика: они растут, даже когда перечитываешь одно и то же и ничего не оседает. «5 часов» ощущается как прогресс, но не отвечает на единственный вопрос - сколько ты воспроизведёшь завтра без подсказки.

Поэтому метрика продукта - доля вспомненного, и она ограничена сверху: план не даёт ставить больше 4-6 часов глубокой работы в день, потому что дальше начинается имитация. Метрика честна ровно настолько, насколько честен её знаменатель - и «часы» этот тест не проходят.

## Стек

HTML / CSS / JavaScript в одном файле · шрифты встроены (base64) · состояние в localStorage · экспорт-импорт через JSON-код · публикация через GitHub Pages. Без фреймворков и сборки.

## Продуктовые решения и trade-offs

| Решение | Альтернатива | Почему так |
|---|---|---|
| Один HTML-файл без бэкенда | Веб-приложение с аккаунтами | Приватность (данные у пользователя), офлайн, ноль зависимостей, нулевой порог входа |
| Метрика «доля вспомненного» | Часы или стрик | Часы создают иллюзию прогресса |
| Потолок 4-6ч | «Чем больше, тем лучше» | Дальше - имитация учёбы; честнее к тому, как работает внимание |
| Редактируемое расписание | Фиксированный шаблон | Жёсткий день не держится под живую неделю |
| Код переноса (JSON) | Синхронизация через сервер | Перенос между устройствами без сервера и аккаунта |
| Вшитая программа как демо | Пустой шаблон | Открыл - сразу видно метод в деле, а не пустые поля |

## Планы

- Встроить оценку вспоминания в сам дашборд (сейчас метрика считается вручную).
- Библиотека готовых программ под разные темы, не только продуктовую.
- PWA-обёртка для установки на телефон как приложение.
- Проверить метод на других людях, а не только на себе.
