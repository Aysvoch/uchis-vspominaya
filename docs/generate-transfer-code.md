# Код переноса: формат и генерация

Код переноса - это состояние расписания одним куском текста. Вставляешь его в дашборде
(**⇄ Перенос между устройствами → Загрузить из кода**) - и расписание, блоки и описания
прописываются сами. Два применения: перенос между устройствами и загрузка готовой недели.

Этот документ - про **сам код** (структуру), не про наполнение тем. Готовый образец - в
[`kody-nedel-pm.txt`](kody-nedel-pm.txt): три недели PM-программы, каждая между строками
`--- BEGIN N ---` и `--- END N ---`. Так должен выглядеть валидный код.

## Что принимает поле «Загрузить из кода»

- **сырой JSON** по схеме ниже - удобно писать руками и генерировать ИИ (рекомендуется);
- **base64-строку** того же JSON - её выдаёт кнопка «Скопировать код» / «Ссылка» в дашборде.

Импорт сам определяет формат. Дни, которых нет в коде (например, Сб/Вс), остаются как есть.

## Схема

```json
{
  "v": 1,
  "sched": {
    "<день>": [ {"id": "<idБлока>", "start": "ЧЧ:ММ", "end": "ЧЧ:ММ"}, ... ]
  },
  "blocks": {
    "<idБлока>": {
      "type": "theory | project | cases | review | rest | routine",
      "label": "Заголовок блока",
      "tagline": "короткий подзаголовок",
      "time": ["ЧЧ:ММ", "ЧЧ:ММ"],
      "purpose": "Для чего блок",
      "howto": "Как использовать эффективно",
      "examples": ["пример 1", "пример 2"],
      "where": "Где искать материал: конкретные источники",
      "diff": "Чем отличается от соседних блоков",
      "custom": true
    }
  },
  "dayinfo": { "<день>": "описание дня" },
  "blocktext": { "<idБлока>": { "label": "...", "purpose": "...", "...": "..." } }
}
```

- `sched`, `blocks`, `dayinfo`, `blocktext` - все необязательные; кладёшь только то, что меняешь.
- `blocks` заводит новые блоки; `blocktext` переопределяет поля уже существующих (в т.ч. встроенных).
- Дни: `Пн Вт Ср Чт Пт Сб Вс` (ровно эти строки).

## Правила валидности

- `id` блоков - латиницей, уникальные; каждый `id` из `sched` есть либо в `blocks`, либо среди встроенных.
- **Встроенные `id`** (можно ставить в `sched`, не описывая заново): `wake`, `wakeeat`, `breakfast`,
  `pause`, `lunch`, `review`, `reviewT`, `english`, `lightday`, `training`, `running`, `weekreview`.
- Время `ЧЧ:ММ`, по возрастанию, встык: `end` одного = `start` следующего.
- `type` задаёт цвет и учёт «глубокой работы»: `theory` / `project` / `cases` считаются в метрику 4-6ч;
  `review` / `rest` / `routine` - нет.
- Поля `purpose` / `howto` / `examples` / `where` / `diff` - обычный текст; их видно при раскрытии блока и можно править в дашборде.

## Промпт для ИИ (сгенерировать код под свою тему)

Подставь `{ТЕМА}`, `{ЧАСОВ}`, `{ДНИ}`. Ответ ИИ - сырой JSON, без ```-заборов и текста вокруг.

```
Собери код учебной недели для моего офлайн-планировщика (метод: учусь через вспоминание,
глубокой работы 4-6 часов в день, блоки на одну тему: впитываешь → делаешь руками →
тренируешь мышление).

Тема: {ТЕМА}
Глубокой работы в день: {ЧАСОВ} часов
Дни: {ДНИ}   (из: Пн Вт Ср Чт Пт Сб Вс)

Верни ТОЛЬКО валидный JSON по схеме. Первый символ ответа "{", последний "}". Правила:
- id блоков латиницей, уникальные; каждый id из sched есть в blocks или среди встроенных
  (wake, breakfast, pause, lunch, review, english - их можно ставить в sched, не описывая).
- Время ЧЧ:ММ, по возрастанию, встык (end одного = start следующего).
- type: theory/project/cases - считаются в глубокую работу; review/rest/routine - нет.
  Суммарно theory+project+cases в день ≈ заданное число часов.
- Заполни каждый блок целиком, особенно where - где искать материал по теме.

Схема одного блока:
{"type":"theory|project|cases|review|rest|routine","label":"...","tagline":"...",
 "time":["ЧЧ:ММ","ЧЧ:ММ"],"purpose":"...","howto":"...","examples":["...","..."],
 "where":"...","diff":"...","custom":true}

Полный ответ:
{"v":1,"sched":{"<день>":[{"id":"...","start":"ЧЧ:ММ","end":"ЧЧ:ММ"}]},
 "blocks":{"<id>":{...}},"dayinfo":{"<день>":"..."}}
```

Готовый пример того, что должно получиться - в [`kody-nedel-pm.txt`](kody-nedel-pm.txt).
